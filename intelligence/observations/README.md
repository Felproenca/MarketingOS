# observations/ — Evidência crua, antes de virar tese
> Localização: /intelligence/observations/
> Camada a montante de experiments.md e patterns.md.
> Aqui não mora conclusão. Mora o que foi observado na realidade — reunião por reunião.

---

## Por que esta pasta existe

> "Uma hipótese sem um lugar para acumular evidência morre por inércia, não por refutação."

Existe uma hipótese estratégica em observação no MarketingOS:

> As empresas não sofrem por falta de ação. Sofrem por agir sem enxergar.
> O que elas acreditam ser o problema raramente é o problema real.

Isso **ainda não é fundação. Não é posicionamento. Não é módulo.**
É uma crença interessante que merece ser validada pela realidade antes de virar arquitetura.

Esta pasta é o mecanismo dessa validação. Nada aqui muda o manifesto, a alma,
o CLAUDE.md, o site ou a oferta. É a menor aposta possível: o menor custo, o
menor risco, o maior potencial de aprendizado.

---

## A regra de captura (a única que importa)

Toda observação registra **um contraste obrigatório**:

```
O que ele acredita ser o problema
        ↓
O que encontramos
```

Esse contraste é o instrumento. Não é um framework impondo uma tese — é o
aparelho de medida da hipótese. E ele é **falseável**:

- Se em ~30 reuniões as duas linhas **batem** → a cegueira não existe.
  A hipótese morre. Economizamos meses. Isso é vitória, não fracasso.
- Se elas **divergem sistematicamente** → temos um ativo que nenhum CRM tem.

Tudo o mais no registro é livre. Só o contraste é obrigatório.

---

## O que NÃO fazer aqui

1. **Não inventar.** Blindspot hipotético é fanfic. Só entra o que foi observado
   em reunião, objeção, diagnóstico ou prospecção **real**. Cada entrada aponta a
   fonte (rastreabilidade).
2. **Não concluir cedo.** Durante o período de acúmulo: sem tese, sem framework,
   sem categoria. Só observação consistente.
3. **Não construir módulo.** "Blindspot Engine" não existe e não deve existir até
   a realidade pedir. Esta pasta é evidência, não produto.

---

## Ciclo de vida (como isto se conecta ao resto do intelligence/)

```
Reunião / objeção / diagnóstico real
  → registrado aqui em observations.md (contraste obrigatório)
  → acúmulo silencioso (~30 reuniões / ~60 dias)
  → padrão de divergência emerge?
      → SIM: vira hipótese formal em experiments.md
      → NÃO (crença ≈ realidade): hipótese registrada como refutada aqui mesmo
  → se confirmado em experimento: sobe para patterns.md
```

Período de acúmulo desta rodada:
- Início: ____________  | Revisão prevista: ____________ (~60 dias depois)
- Reuniões registradas: 0 / meta ~30

---

## Como registrar

1. Abra `observations.md`.
2. Copie o bloco de `_template.md` para o topo da lista.
3. Preencha o contraste obrigatório. O resto, só se você tiver.
4. Não edite observações antigas para "encaixar" numa tese. Evidência é histórica.
